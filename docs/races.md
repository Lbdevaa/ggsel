# Состязательные сценарии

Каждый сценарий реализован в `scripts/race.mjs` и печатает строку «сценарий → ожидание → факт → OK/FAIL». Таблица заполняется по мере реализации этапов.

| # | Сценарий | Ожидание | Этап | Статус |
|---|---|---|---|---|
| R1 | 50 параллельных вебхуков `paid` с разными `event_id` по одному заказу | 1 выдача, 1 ключ списан у поставщика | 2 | PASS |
| R2 | 20 повторов одного `event_id` | состояние заказа не меняется | 2 | PASS |
| R3 | Вебхук `paid` до создания заказа, затем создание заказа | заказ доходит до `delivered` | 2 | PASS |
| R4 | `paid` и `failed` вперемешку параллельно | итог `delivered`, `failed` после `paid` игнорируется | 2 | PASS |
| R5 | 30 параллельных `POST /api/orders` с одним `order_id` | 1 заказ в БД | 2 | PASS |
| R5b | 10 параллельных созданий и 10 `paid` по одному заказу одновременно | 1 заказ, 1 выдача | 2 | PASS |
| R6 | Пустой пул → restock → 10 параллельных reissue | `out_of_stock` без падения, после restock ровно 1 ключ | 3 | |
| R7 | Поставщик A в режиме таймаута, затем таймаут снят | повтор возвращает тот же код, задвоения нет | 3 | |
| R8 | 50 параллельных заказов с промокодом `LIMIT3` | ровно 3 применены, остальные `409` | 4 | |
| R9 | 50 параллельных заказов с `ONCEONLY` | ровно 1 применён | 4 | |

## Как запустить

- Против живого стенда: `npm run dev`, затем `npm run race` (или `RACE_REPEAT=10 npm run race`). Скрипт печатает по строке на сценарий и итоговый инвариант: у поставщика списано ровно столько ключей, сколько заказов доведено до `delivered`.
- В процессе теста без стенда: `npm test`. Файлы `backend/test/races.test.js` и `backend/test/supplier-failures.test.js` поднимают API с БД в памяти и заглушку поставщика на случайных портах.
- В CI оба варианта: `node --test` и `race.mjs` против `docker compose`.

## Дополнительно покрыто тестами

| Сценарий | Ожидание | Статус |
|---|---|---|
| Поставщик выдал ключ, но ответ завис (таймаут клиента) | повтор с тем же `request_id` возвращает тот же ключ, списан 1 | PASS |
| Поставщик недоступен (порт закрыт) | после ретраев `delivery_failed`, заказ восстановим | PASS |

| Пустой пул | `out_of_stock` без падения, ключей не списано | PASS |
| Вебхук с чужой суммой | сохранён, не применён | PASS |
